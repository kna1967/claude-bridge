# v5 軸⑮ 過去予測の答え合わせ

## 概要

過去に下した投資判断(エントリー / 見送り / 利確 / 損切り)について、**「予測 vs 実績」を定量的に検証し、ズレの原因を分解してテンプレに還元する**ためのシステム。

軸⑭が「保有中の機械的執行」を担うのに対し、軸⑮は「**判断後の検証ループ**」を担う。

---

## なぜ「答え合わせ」が必要か

### 投資の最大の落とし穴 — 検証なき自己評価

- 利益が出ると「自分の分析力が高い」と感じる(過信バイアス)
- 損失が出ると「市場が悪い」と外部要因に帰す(自己防衛バイアス)
- どちらも**判断プロセスの改善には繋がらない**

### 検証なしで起きる現象

- 同じパターンの誤判断を繰り返す
- 「たまたま」の成功を「実力」と誤認する
- テンプレに書いた論点を実際の判断で軽視している自覚が持てない
- 過去の銘柄ノートが「読み返されない遺物」になる

### 軸⑮の目的

1. 判断の**正解率ではなくプロセスの妥当性**を検証する
2. ズレの原因を**5分類**(ファンダ / 需給 / タイミング / 外的要因 / 自己バイアス)で言語化する
3. 検証結果を**テンプレ改訂に還元**する(v5.2 → v5.3 への進化エンジン)

---

## A. 検証フレーム — 何を、いつ、どう検証するか

### A-1. 検証対象の特定

すべての判断を検証対象にする。

| 判断種別 | 検証タイミング |
|---|---|
| エントリー(買い) | 1ヶ月、3ヶ月、6ヶ月、1年 |
| 段階利確 | 利確後1ヶ月(残保有分の動向) |
| 損切り | 損切り後1ヶ月、3ヶ月(再上昇していないか) |
| **見送り判断** | **3ヶ月、6ヶ月**(機会損失の検証) |
| ウォッチリスト入り | 再評価トリガー到達時 |

> **重要**: 「見送り」も判断であり、検証対象。買わなかった銘柄が大きく上がったとき/下がったときは特に貴重なデータ。

### A-2. KPI設計 — 「合っていたか」をどう測るか

検証は単純な「株価が上がったか/下がったか」では不十分。**判断時の予測内容に対応するKPIを設計**する。

| 元の予測内容 | 検証KPI |
|---|---|
| 「業績好転で株価上昇」 | 実績営業利益 vs 会社予想、株価 vs 目標株価 |
| 「需給悪化で短期下落」 | 信用倍率推移、出来高変化 |
| 「決算でポジティブサプライズ」 | 実際の決算結果 vs コンセンサス |
| 「アナリスト目標まで+49%」 | 株価到達率、目標株価そのものの修正履歴 |
| 「PBR 1倍割れ修正期待」 | PBR推移、還元方針の追加発表有無 |
| 「政策カタリスト発動」 | 法改正/規制発表のタイミングと影響度 |

### A-3. 外的要因の控除

ズレが「自分の判断ミス」か「外的要因」かを切り分ける。

| 外的要因 | 控除すべきか |
|---|---|
| TOPIX/S&P 500の市場全体変動 | **同期間の指数騰落率を引き算** |
| セクター全体のローテーション | 同業比較で相対評価 |
| 円高/円安の急変 | 為替影響を分離(海外売上比率で按分) |
| 想定外の地政学イベント | コメント記録、ただし「想定外として無視」が許される回数は記録 |
| 決算リーク・特別損益 | 一過性として実力ベースで再評価 |

> 控除して残った差分が **「自分の判断の質」を映す純粋なシグナル**。

---

## B. ズレの原因分解 — 5分類

判断と実績にズレが出たとき、原因を以下の5つに分類する。

### B-1. ファンダの読み違い
- 業績予想を高く/低く見積もりすぎた
- セグメント別の利益構造を誤解していた
- 海外事業の不振/好転を見落とした
- バズワード(AI、DX、TX)に酔って実力指標を見損ねた

**例(NEC型)**: ヘッドライン「売上減」だけで急落したが、Non-GAAP営業利益は+5.7%伸長 → ヘッドライン依存は読み違いカテゴリ。

### B-2. 需給の読み違い
- 信用倍率の絶対値だけで判断した(出来高比で見れば消化可能だった等)
- スマートマネーの動向を確認していなかった
- 大口ロックアップ解除/IPO株の流入を計算に入れていなかった
- 「プロの罠」(意図的な売り浴びせ・買い煽り)に気づかなかった

**例(IHI型)**: 信用倍率47倍を「過熱」と判定したが、テーマ性が強い銘柄では正常化に半年〜1年要する → 判定の時間軸を誤った。

### B-3. タイミングの読み違い
- 決算前にエントリーした(イベント直前のリスクを軽視)
- 政策カタリスト発表を「もう織り込み済み」と判断したが、実際には未織り込みだった(or その逆)
- マクロサイクルの位置を誤認

### B-4. 外的要因(自分のミスではない部分)
- 想定外の地政学イベント
- 突然の規制発表
- 競合の予想外の戦略変更
- → これは「外的要因として除外」とコメントするが、**頻度が高い場合は「想定外バッファ」をリスク管理で恒常化**する

### B-5. 自己バイアス(最も重要、最も見逃しやすい)
- 確証バイアス: 自分の仮説を支持する情報のみ重視
- ストーリー先行: 「物流DXで伸びる」等のナラティブに酔った
- 損失回避: 損切りラインを後ろ倒しした
- 保有効果: 既保有銘柄を過大評価
- 直近バイアス: 直前1週間の値動きで判断
- FOMO: 「もっと取れるはず」で利確を先延ばし
- 判断疲れ: 大型判断の直後に別判断を下した

## C. フィードバックループ — テンプレ改善への還元

### C-1. 1事例 → 即時修正
明確なズレ要因が特定できたら、当該軸のチェック項目を**個別銘柄ノート末尾に追記**する。

例: NEC分析で「ヘッドライン売上減で急落」のパターンを認識
→ 軸①の「バズワード警戒」に「**売上だけでなく利益指標(調整後・Non-GAAP)を必ず確認**」を追記。

### C-2. 3事例蓄積 → 軸の構造改訂
同じ種類のズレが3銘柄以上で観測されたら、**メインテンプレ(13軸)の構造改訂**を検討する。

例: NEC・サトーHD・IHIの3銘柄でアフターマーケット/リカーリング収益の分析が必要だと判明
→ v5.2 で軸②に「H. アフターマーケット分析」を新設。

### C-3. 自己バイアス検出 → 認知バイアスチェックリスト強化
B-5(自己バイアス)が頻出する場合、**認知バイアスチェック欄に新項目を追加**する。

例: 「ロジックは正しかったのにエントリーしすぎた」という事象が複数回 → 「ライオン化警戒」項目を軸⑭エントリー前チェックに追加。

### C-4. 改訂履歴の記録
すべての軸改訂は、テンプレ末尾の改訂履歴に「どの銘柄の検証から得た知見か」を明記する。

## D. 検証ノートの運用(答え合わせフォルダ)

### D-1. ノート作成のタイミング
- 大きな決算イベント後
- 1ヶ月/3ヶ月/6ヶ月/1年の振り返り時
- 軸⑭発動時(段階利確/損切り)
- 月末/四半期末のまとめレビュー
- ウォッチリスト銘柄の再評価トリガー到達時

### D-2. ノート構造(`答え合わせ/_テンプレ_予測検証.md` 参照)

```
1. 検証対象(銘柄、元の判断日、判断内容)
2. 元の予測の要約(軸別の主張、根拠)
3. 実績(KPIごとに数値)
4. ズレの分析(B-1〜B-5の5分類で言語化)
5. 外的要因の控除
6. テンプレへの還元(具体的な改訂提案)
7. 自己評価(プロセスの妥当性。結果ではなく「同じ判断を下せるか」を問う)
```

### D-3. ノート命名
`[Ticker]_[銘柄名]_検証_[検証日].md`
例: `6701_NEC_検証_2026-08-15.md`(エントリーから3ヶ月後)

### D-4. 元の銘柄ノートとの紐付け
- 検証ノート側に「元ノート: `[[6701_NEC_2026-05-08]]`」を必ずリンク
- 元ノート側にも「答え合わせ: `[[6701_NEC_検証_2026-08-15]]`」を追記

## E. 検証実例(簡略)

### 実例1: NEC(6701)— エントリー判断の検証フレーム想定

| 元の予測(2026-05-08) | 検証KPI | 想定検証日 |
|---|---|---|
| 「アナリスト目標6,008円まで+49%」 | 株価到達率 | 2026-08, 2026-11 |
| 「Non-GAAP営業利益+5.7%予想は実現」 | 27.3期1Q決算進捗率 | 2026-08(1Q決算後) |
| 「BluStellar売上シェア向上が鍵」 | RFID/サブスク売上の開示 | 同上 |

→ 1Q決算後に答え合わせノートを起こす。

### 実例2: サトーHD(6287)— 見送り判断の検証フレーム想定

| 元の判断(2026-05-09) | 検証KPI | 想定検証日 |
|---|---|---|
| 「5/15本決算待ち、打診のみ可」 | 5/15ガイダンス、還元方針 | 2026-05-16 |
| 「PBR 1倍回復には還元強化が必要」 | 自社株買い発表の有無 | 同上 |
| 「海外不振継続シナリオ」 | 海外セグメント利益率 | 2026-08(1Q) |

→ 5/15直後に「予測検証 v1」、3ヶ月後に「予測検証 v2」を起こす。

### 実例3: IHI(7013)— 見送り判断の検証フレーム想定

| 元の判断(2026-05-09) | 検証KPI | 想定検証日 |
|---|---|---|
| 「信用倍率47倍は過熱、本格買い見送り」 | 信用倍率推移、株価高安 | 2026-08, 2027-02 |
| 「PBR 5.42倍は割高」 | PBR推移、業績との連動 | 同上 |
| 「再評価トリガー: 信用倍率15倍 or PBR 3倍」 | トリガー到達日 | トリガー時 |

→ **見送りの答え合わせ**は、機会損失検出の貴重な事例になる(信用倍率が下がる前に株価が上がってしまう可能性も検証)。

## F. 自己バイアス検出のチェックリスト

検証ノートを書く時、以下を自問する。

- [ ] 結果が良かったから「プロセスも正しかった」と思っていないか?
- [ ] 結果が悪かったから「外的要因のせい」と逃げていないか?
- [ ] 損切り回避(リスク回避)を「我慢強さ」と美化していないか?
- [ ] 利益確定の遅れを「強気の継続保有」と正当化していないか?
- [ ] 「次は気をつける」だけで終わらせず、テンプレに反映したか?
- [ ] 同じ種類のズレが過去にもなかったか(過去の検証ノートを再読)
- [ ] AIや第三者に客観意見を求めたか?

## G. 検証の頻度・分量

### 月次レビュー(必須)
- すべての保有銘柄の含み損益を一覧化
- 軸⑭発動の有無を確認
- 重要決算があった銘柄の答え合わせノート起こし

### 四半期レビュー(必須)
- 過去3ヶ月の判断をまとめて検証
- ズレ要因の集計(B-1〜B-5のどこが多いか)
- テンプレ改訂候補のリストアップ

### 年次レビュー(必須)
- 1年の総括
- 軸の追加/削除の議論
- 哲学レベルの再検証(`v5_ハイエナ投資哲学.md` を読み返す)

### 「重い」検証は年4回で十分
- 月次は「軽い更新」で済ませる
- 四半期/年次に「重い分析」を集中させる
- 検証疲れで運用が止まることを防ぐ
